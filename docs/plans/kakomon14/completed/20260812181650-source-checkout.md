# ソース取得と配置(50-source.sh)

## 目的

isucon14のwebappソースをbastion上に配置する。公式のtarball転送方式(`webapp.tar.gz`)ではなく、git cloneで完結させる。

## やること

- isucon14をコミットハッシュ固定でclone(または既存cloneをfetch)する
- `/home/isuren/webapp`相当のパスにgo/sqlディレクトリが揃うように配置する(シンボリックリンクかrsyncかを決める)
- 所有者をisurenにする

## 完了条件

`/home/isuren/webapp/{go,sql}` が存在し、isuren所有になっていること

## 決定事項

- isucon14はコミット`53f8b627e040c30ebec600457c6c97da008b84b0`(AI参照用ローカルコピーのHEAD、2024-12-13時点)に固定してclone
- `/home/isuren/webapp`配下の配置はrsyncコピーではなくシンボリックリンク(`/home/isuren/isucon14/webapp`へ)を採用。frontend-buildタスクでの生成物がそのままcloneツリーに反映されるようにするため
- シンボリックリンク自体へのchownは行わない。Linuxではシンボリックリンク自体のパーミッション/所有者はカーネルからほぼ無視され、実際のアクセス制御はリンク先の実体に対して行われるため機能的に不要
- **重要な発見**: このbastion(Ubuntu 26.04)の`chown`は`/usr/bin/chown -> ../lib/cargo/bin/coreutils/chown`(uutils coreutils 0.8.0、GNU coreutilsではない)で、`-h`/`--no-dereference`がexit 0を返すのに実際にはlchownしないバグがある。通常ファイルへの`chown`(`-h`なし)は正常動作を確認済み。今後シンボリックリンクをchownする場面があれば要注意
- `scripts/kakomon14/50-source.sh`をbastion上で2回実行し、1回目clone→2回目fetchのみ(冪等)を確認済み。`/home/isuren/webapp/{go,sql}`がisuren所有であることも確認済み(完了条件を満たす)
