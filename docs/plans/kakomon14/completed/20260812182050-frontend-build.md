# frontendビルド(80-frontend.sh)

## 目的

nginxのrootが指す`webapp/public/`を用意する。公式は`make_latest_files.sh`でtar.gzに同梱しているが、`webapp/public`はisucon14の`.gitignore`に入っているため、cloneしたツリー内でビルドしてもツリーは汚れない。

## やること(重要な順序制約あり)

- isurenユーザーでNode/pnpmを使い、`frontend`ディレクトリで`pnpm install --frozen-lockfile && pnpm run build`を実行する
- ビルド成果物(`build/client/`)を`webapp/public/`にコピーする
- **frontendのビルドは、bench側のビルド/実行より必ず先に行う**。`frontend/vite.config.ts`のプラグインがビルド時に`bench/benchrun/frontend_hashes.json`を再生成するため、順序を守らないとベンチの負荷走行中に静的ファイルのMD5検証が全て失敗する(`--skip-static-sanity-check`はPrepare時のみ有効でこの検証は止められない)

## 完了条件

`frontend_hashes.json`に記載された各ファイルのmd5と、`webapp/public/`配下の実ファイルのmd5が全て一致すること

## 決定事項

- **重要な発見**: `pnpm install`中にOOM killerがnodeプロセスを殺す事象が発生した。t4g.small(メモリ1.8GiB、swap無し)では`pnpm install`(877パッケージ)のメモリ消費を吸収しきれない。今回は一時的にt4g.mediumへインスタンスタイプ変更(stop→modify-instance-attribute→start)して回避した。恒久対応(swap追加等)は別途検討の余地があり、Packerでの本番相当ビルド時も同じ制約に当たる可能性が高い
- pnpm 10以降はesbuild/@swc/core等のpostinstallスクリプトをデフォルトでブロックする(strictDepBuilds)。allowBuildsのワイルドカード(`*`)指定はpnpm本体が未対応のため、`scripts/kakomon14/pnpm-workspace.kakomon14.yaml`に承認対象(esbuild/@swc/core)を明示列挙し、`pnpm install`より前に配置することで1回目のinstallから通るようにした
- `scripts/kakomon14/80-frontend.sh`をbastion上で実行し、`frontend_hashes.json`の全61エントリとwebapp/public配下の実ファイルmd5が一致(missing 0, mismatches 0)することを確認済み(完了条件を満たす)
