# preflightチェック(00-preflight.sh)

## 目的

Ubuntu 26.04 arm64というbastionの環境が、公式想定(Ubuntu 24.04 amd64)と違う部分でどこに影響が出るかを先に洗い出す。

## やること

- mysql-server/nginx/curl/gzipのバージョン・可用性を確認する
- Go版に絞った場合に必要な最小aptパッケージを確定する(公式apt roleの大半は他言語のネイティブ拡張ビルド用なので削減できる見込み)
- miseで管理するgo/node/pnpmのバージョンを決める(Goは`go.mod`の`go 1.23`要求を満たすこと、Nodeは`package.json`の`engines`要求、pnpmは`pnpm-lock.yaml`の`lockfileVersion`に合わせる)

## 完了条件

必要パッケージ一覧とバージョンが確定していること。26.04で明らかな不都合(特にmysql-serverのメジャーバージョン差異)が見つかった場合は、ベースAMIを24.04に切り替えるかどうかをここで判断する

## 決定事項

- OS: Ubuntu 26.04 LTS(resolute)/ arm64、公式想定(24.04 amd64)との差異は主にmysql-serverのメジャーバージョン
- mysql-server: apt candidateは8.4.10。まず8.4でwebapp/sqlのスキーマ流し込み・isucon userのGRANTが通るか実地確認する方針(モダナイズ優先で将来9.7 LTS化も検討余地あり。9.7はUbuntu標準リポジトリになく、MySQL公式aptリポジトリ追加が必要になるため今回は見送り)
- nginx: apt candidate 1.28.3
- curl/gzip: ベースイメージに導入済み(curl 8.18.0 / gzip 1.14)、追加インストール不要
- Go: miseで1.26.5を管理(全go.modの要求`go 1.23`を満たす最新版。モダナイズ優先で固定バージョンより最新追従を選択)
- Node: miseで24.19.0を管理(package.jsonの`engines`は`>=20.0.0`だが、モダナイズ優先で24系最新を採用)
- pnpm: miseで11.21.0を管理(`pnpm-lock.yaml`の`lockfileVersion: '9.0'`はpnpm 9/10と共有形式で、11で新形式に上がるが、frontendの`package.json`に`pnpm`フィールドや`.npmrc`がなく設定の読み込み先変更の影響を受けないため問題なし)
- 最小aptパッケージ: `git` / `mysql-server` / `nginx` のみ。公式`roles/apt`の大量のCライブラリ系パッケージ(`libxml2-dev`等)はxbuild経由の他言語(Ruby/PHP/Python/Perl)ビルド用であり、Go×mise構成では不要と判断(`go-sql-driver/mysql`はpure Go実装でcgo不使用のため`libmysqlclient-dev`も不要)
