# nginx TLS対応(90-nginx.shのENABLE_TLS)

## 目的

本番相当のHTTPS経路も検証できるようにする。公式のTLS証明書は失効済み(2025年2月)なので使わず、自己署名証明書で代用する。ベンチはTLS検証をしない(`InsecureSkipVerify`)ため自己署名で問題なく通る。

## やること

- 自己署名ワイルドカード証明書(`*.xiv.isucon.net`)を生成する(有効期限が近い/存在しない場合のみ再生成する冪等な作りにする)
- 公式の`isuride.conf`相当の443 vhostを追加する(`ENABLE_TLS`環境変数で切り替え可能にする)
- ブラウザ確認用に`/etc/hosts`の`isuride.xiv.isucon.net`エントリを活用する

## 完了条件

`go run . run --target https://xiv.isucon.net --addr <bastion-ip>:443 -t 60` が成功すること

## 決定事項

- 自己署名証明書はCN/SAN=`*.xiv.isucon.net`のワイルドカード証明書とし、公式と同じ`/etc/nginx/tls/_.xiv.isucon.net.{crt,key}`に配置した。`openssl x509 -checkend 2592000`(30日)で有効期限を判定し、存在しない/期限切れ間近のときのみ再生成する冪等な作りにした
- HTTP版と同様、bot避け用の443デフォルトvhost(dummy証明書)は本番運営向けのセキュリティ対策でありこのbastionでは不要と判断し、本命の443 vhost(`xiv.isucon.net`/`*.xiv.isucon.net`)のみ追加した
- `ENABLE_TLS=true scripts/kakomon14/90-nginx.sh`をbastion上で2回実行し、1回目`generated`/`changed`→2回目すべて`already valid`/`already up to date`を確認済み。`nginx -t`の構文チェックも成功
- **重要な発見**: benchを`runuser -u isuren`経由で実行しようとすると、cwd(`/home/ubuntu/works/...`)がisurenから読めず失敗する(`/home/ubuntu`が750でisurenはグループ外)。回避策として、isurenのmiseでインストール済みのgoバイナリ(`/home/isuren/.local/share/mise/installs/go/<version>/bin/go`。install先が755で他ユーザーからも実行可能)を、実行ユーザーはubuntuのまま直接フルパス指定で呼ぶ形にした
- `sudo -u ubuntu bash -c 'cd .../isucon14/bench && /home/isuren/.local/share/mise/installs/go/1.26.5/bin/go run . run --target https://xiv.isucon.net --addr 127.0.0.1:443 -t 60'`で`pass=true`・スコア=871を確認済み(完了条件を満たす)。ブラウザ確認用の`/etc/hosts`エントリはローカルPC側の対応であり、bastion側スクリプトの範囲外と判断し追加しなかった
