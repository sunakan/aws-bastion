# matcherのsystemd化(75-matcher.sh) 【マイルストーンB】

## 目的

Ansibleの`isuride-matcher.service`相当を再現する。実体は専用バイナリではなく、`/api/internal/matching`を一定間隔でcurlし続けるだけのループ。

## やること

- `isuride-matcher.service`を配置する。公式は`https://isuride.xiv.isucon.net/api/internal/matching`(nginx経由・TLS依存)を叩くが、`http://127.0.0.1:8080/api/internal/matching`への直叩きに変更する(nginx/TLSを丸ごとバイパスできる)
- `$ISUCON_MATCHING_INTERVAL`(0.5秒)はEnvironmentFile経由でそのまま使う
- `systemctl daemon-reload && systemctl enable --now isuride-matcher`

## 完了条件

`go run . run --target http://localhost:8080 -s -t 30` でスコアが0でないこと(matcherが動いていないとエラーは出ずスコアだけ伸びない点に注意)

## 決定事項

- ユニットの`After=`は他言語(node/perl/php/python/ruby/rust)分を削除し、Go版のみ(`isuride-go.service`)に絞った
- `scripts/kakomon14/75-matcher.sh`をbastion上で2回実行し、1回目changed→2回目already up to dateを確認済み
- `60-initdb.sh`でDBをリセットした上で`go run . run --target http://localhost:8080 -s -t 30`を実行し、`pass=true`・スコア=512(0でない)を確認済み(マイルストーンB達成)。CODE=26のエラーが1件出たが、深掘りはしておらずmatcherのセットアップに起因するものかは未確認(完了条件自体は満たしている)
