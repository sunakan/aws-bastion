# DB初期化(60-initdb.sh)

## 目的

Ansibleのwebapp roleが行うDB初期化(DROP/CREATE→スキーマ→初期データ投入)を再現する。

## やること

- `DROP DATABASE IF EXISTS isuride; CREATE DATABASE IF NOT EXISTS isuride;` を実行する
- `ISUCON_DB_*`環境変数をexportした状態で`webapp/sql/init.sh`を実行する(`1-schema.sql`→`2-master-data.sql`→`3-initial-data.sql.gz`が流れる)
- `mysql`/`gzip`コマンドが利用可能であることを前提にする(preflightで確認済みのはず)

## 完了条件

初期データ投入後、想定件数のレコードが入っていること(例: `select count(*) from isuride.chairs`)

## 決定事項

- `init.sh`は`/home/isucon/env.sh`(固定パス)を`test -f`でsourceしようとするが、bastionには`isuren`しかおらず存在しない。デフォルト値がenv.shの内容と一致するため実害はないが、タスク方針通り`ISUCON_DB_*`を明示exportして渡す形にした
- このスクリプトは他のスクリプトと違い、2回目以降もchanged/already判定を行わず毎回DROP&CREATEする。本番の`/api/initialize`と同じ「常にリセットする」動作が正しい仕様のため
- `scripts/kakomon14/60-initdb.sh`をbastion上で2回実行し、いずれも`chairs=500`が投入されることを確認済み(1回目: chairs=500/users=559/owners=5/rides=750も確認)
